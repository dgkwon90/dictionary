# ADR-0010: 제품 재설계 v2 — 검색과 학습을 분리한다

- 상태: 채택 (2026-08-05)
- 관련: ADR-0007(파생 상태), ADR-0008(알림), PRD §6·§10·§11·§14

## 배경

v1은 "찾아본 것"과 "배우기로 한 것"을 구분하지 않았다. 검색할 때마다 `learner_items` 행이
생겼고, 그래서 학습 목록은 **사용자가 지금까지 타이핑한 모든 것의 로그**였다. 실사용에서
드러난 증상 셋:

1. 인박스의 새 것/저장/보관 축이 무의미했다 — "저장과 보관이 뭐가 다른지 모르겠다."
2. 학습 목록에 배울 생각이 없던 단어가 가득했다. 목록이 거짓이면 복습도 거짓이 된다.
3. 문장을 검색하면 문장 전체가 하나의 학습 항목이 됐다. 정작 몰랐던 건 그 안의 단어 하나인데
   그 단어는 어디에도 남지 않았다.

핵심 오진단은 축이었다. 중요한 것은 "이 검색을 어디에 보관하는가"가 아니라 **"이 검색을
어떻게 할지 정했는가"** 였다.

## 결정

검색 기록과 학습 목록을 **다른 것**으로 만든다. 검색은 자유롭게 쌓이고, 학습 목록에는
사용자가 명시적으로 담은 것만 들어간다.

```
검색(capture) ──[학습할래요 / 단어 고르고 완료]──> 학습 항목(learner_items)
       └────────[삭제]───────> discarded
```

`captures.triage_state`: `unseen` → `needs_selection`(문장) → `learning` / `discarded`.
학습 등록은 이 경계를 넘을 때만 일어난다.

### D1. 단어/문장 판정은 서버가 자동으로, 사용자가 뒤집는다

검색 전 토글을 두지 않는다. 제품의 약속이 "단축키로 **즉시**"인데 매번 묻는 것은 그 약속을
깎는다. 판정은 거의 공백 개수 문제라 자동 정확도가 높고, 틀리면 결과 화면에서 한 번 눌러
고친다(`POST /v1/searches/{id}/kind`).

AI의 `input_type`과 서버 판단이 갈리면 **서버가 이긴다**(`explain.LearnKind`). 문장을 단어로
오분류하면 단어 선택 흐름 전체를 건너뛰어 제품이 조용히 망가지는데, 그 비용이 반대 방향보다
훨씬 크기 때문이다.

### D2. 문장은 `knowledge_items`의 한 종류다

별도 테이블을 만들지 않는다. 카드·학습·통계 쿼리를 그대로 재사용할 수 있고, 별도 테이블은
다형 FK와 전면 UNION을 부른다.

단 UNIQUE 키에서 `item_type`을 뺐다: `UNIQUE(normalized_key, learn_kind)`. `item_type`은 AI가
5지선다로 고르는 값이라 `stale`이 한 번은 `word`, 다음엔 `term`으로 오면 행이 갈라져 "횟수만
누적"이 확률적으로 깨진다. **`normalized_key`도 서버가 계산한다** — AI가 준 키를 그대로 쓰면
긴 문장의 키를 AI가 잘라 반환했을 때 서로 다른 두 문장이 조용히 병합된다.

### D3. cloze 카드는 소유자와 문맥을 나눠 붙인다

`review_cards.knowledge_item_id`(소유자) + `context_knowledge_item_id`(문맥).

| 카드 | 소유자 | 문맥 |
|---|---|---|
| 단어 뜻 맞추기 | 단어 W | NULL |
| 문장 뜻 맞추기 | 문장 S | NULL |
| cloze (S 안의 W) | **W** | **S** |

단어에만 매달면 같은 단어가 여러 문장에서 나올 때 카드가 몰리고, 문장에만 매달면 단어 실력이
문장 정답률로 기록돼 "자주 틀린 단어"가 오염된다. "문장 복습 = 뜻 맞추기 + cloze"는 스키마가
아니라 세션 쿼리(`knowledge_item_id = S` ∪ `context_knowledge_item_id = S`)로 만족시킨다.

### D4. 선택 원장은 `capture_items` 확장

새 테이블 대신 `char_start`/`char_end`(문장 내 위치)와 `selected_at`(NULL=미선택)을 더했다.
같은 단어가 한 문장에 두 번 나오는 경우와 사용자가 임의 구간을 고르는 경우가 컬럼 둘로
흡수된다. `UNIQUE(capture_id, knowledge_item_id, role)`은 원래 import 경로에만 있던 자연키라,
인덱스를 만들면서 라이브와 백업 복원이 처음으로 같은 규칙을 쓰게 됐다.

### D5. 정답률은 계산값이고, `again`만 오답이다

| rating | 판정 | 근거 |
|---|---|---|
| `again` | **오답** | "모르겠음" |
| `hard` | **정답** | "떠올렸으나 힘들었다" — 오답 처리하면 정직한 자가보고를 처벌해 등급 부풀리기를 부른다 |
| `good`/`easy` | 정답 | |

`accuracy = correct_count / attempt_count`를 **저장하지 않는다**. 저장하면 카운터와 언젠가
어긋나고, 어긋난 순간 어느 쪽이 맞는지 알 방법이 없다.

- **`mastery_score` 삭제**: 정답률이 아니면서 정답률 자리를 차지했고, `accuracy`가 답하는
  질문을 더 잘 답하지 못했다.
- **`wrong_count` → `unknown_count` 개명**: 값의 실제 의미는 "모른다고 선언한 횟수"인데 이름이
  "복습 오답 수"로 읽혀 오구현을 유도했다. 복습 오답 수는 `attempt_count - correct_count`다.
- **연습도 이제 기록된다**: `review_logs(source='practice')` + 카운터. 단 `due_at`/`state`/
  `reps`/`interval_days`는 건드리지 않는다 — 연습이 복습 일정을 흔들지 않는다는 성질을 지키면서
  "연습도 실력"을 만족시킨다.

### D6. "정답률 100% 제외"는 `WHERE`가 아니라 `ORDER BY`다

문구 그대로 구현하면 `good` 한 번 받은 카드가 즉시 100%가 되어 로테이션에서 **영구 이탈**한다.
앱이 일주일 뒤 조용히 멈춘다. 후순위 정렬만 하고 완전 제외는 하지 않는다(`min_attempts_for_mastery`
기본 3). 같은 조건을 `DueCards`·`CountDueCards`·대시보드 **세 곳에 같이** 적용한다 — 안 하면
"알림은 오는데 목록은 비어 있는" 불일치가 생긴다.

### D7. AI 스타일은 열되, 스키마는 열지 않는다

`ai_prompt_style`(자유 텍스트 2000자)과 `ai_examples_count`(0~5)를 설정으로 노출한다.
**임의 스키마 편집은 하지 않는다**: `responseSchema()` 출력은 고정 Go 구조체로 파싱되고 그게
지식 추출 전체를 구동한다. 사용자가 필드명을 바꾸면 저장이 실패해 capture가 영구 `failed`로
남고 **복구 경로가 없다** — 사용자는 자기가 무엇을 깼는지 모른다. 기본 스키마는 읽기전용
샘플 + 복사 버튼으로만 보여준다.

### D8. 동기화는 지금 만들지 않되, 나중에 막히지 않게만 한다

- `sync_outbox`와 capture 생성 시 outbox 쓰기 유지(`NEULSANG_SYNC_URL` 미설정 시 no-op).
- **`updated_at`을 동기화 대상 전 테이블에 추가.** 지금 비용은 컬럼 하나, 나중 비용은
  마이그레이션 + 정답 없는 백필이다.
- **하드 삭제 금지**: `learner_items.status='removed'`, `captures.triage_state='discarded'`,
  `notifications.deleted_at`(0003). 사라진 행은 "동기화 안 된 행"과 구별할 수 없다.
- 지금 만들지 말 것: `sync_version`, lamport/vector clock. 단일 사용자 다기기에는
  `updated_at` + LWW로 충분하다.

## 결과

- **마이그레이션은 재작성했다.** 보존할 학습 데이터가 없었기 때문에(재설계 시점 실측:
  `review_cards` 0행, `review_logs` 0행) 변환기 대신 `0001_init.sql`을 새로 썼다. 기존 개발
  DB는 checksum 불일치로 기동을 거부하며, 에러 문구가 DB 경로와 조치를 담는다.
- 화면이 바뀌었다: 인박스 5탭 → **검색 기록**(미확인/전체 × 단어/문장) + **학습 목록**
  (학습 중/제외한 것 × 전체/오늘/이번 주/자주 틀림).
- `POST /v1/knowledge/{id}/mark-unknown`이 사라졌다. 학습 등록은 이제 검색 기록의
  `learn`/`selections/complete`가 담당한다.
- 알림 route `"Inbox"` → `"Search History"`(0002). 이 값은 DB에 저장되므로 개명은 Go·Rust·
  프론트 세 곳 + 저장된 행을 한 번에 바꿔야 한다.

## 대안과 기각 사유

- **인박스 상태만 손보기**: 축 자체가 틀렸으므로 이름을 바꿔도 같은 문제가 남는다.
- **문장 전용 테이블**: 다형 FK와 UNION이 카드·통계·백업 전 경로로 번진다(D2).
- **검색 전 단어/문장 토글**: "즉시"를 깎는다(D1).
- **정답률 컬럼 저장**: 원장 불일치(D5).
